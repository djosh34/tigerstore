No fixed cluster-wide operation total or quorum-wide completion count is asserted.

**Why PageWriter is one full value stage here:** benchmark keys are short fixed-format names (`inputs/workload/main.go:119`) and the scoped unauthed requests contain one 1 KiB value plus small metadata; the padded WAL record is below 4 KiB. PageWriter's page size is 4,096 (`source/server/storage/wal/encoder.go:36`, `source/server/storage/wal/decoder.go:34`). Its normal branch copies all bytes; its overflow branch copies a slack prefix, flushes, then recursively copies the tail. The direct-page bypass requires `len(p) > pageBytes` and therefore cannot bypass any part of this short record. Split copies into the same buffer count as one full-value-equivalent stage, not two full copies. For large keys/auth metadata/large multi-value Txns this specific fixed assertion would require rechecking and must not be generalized.

**Optional codec coalescing:** before owning protobuf decode, grpc `MaterializeToBuffer` returns a refcounted existing buffer when BufferSlice length is one; with multiple buffers it copies to one destination (`deps/google.golang.org_grpc@v1.83.2/mem/buffer_slice.go:105-117`, `deps/google.golang.org_grpc@v1.83.2/mem/buffer_slice.go:79-83`). Let C be 0 or 1 additional full-input stage per request according to actual codec input segmentation. Frame segmentation was not established, so no unconditional accumulation copy is charged and no single-frame assumption is made. HTTP/bufio/transport receive accumulation and compaction are excluded. Thus the known immediate input result is **8+C** on successful writes and **7+C** on a comparison failure, not a physical total.

**Zero-copy assignments are not stages.** Raft proposal's `Entry{Data:data}` (`deps/go.etcd.io_raft_v3@v3.7.0/node.go:471-473`), MemoryStorage append (`deps/go.etcd.io_raft_v3@v3.7.0/storage.go:293-320`), and unstable append (`deps/go.etcd.io_raft_v3@v3.7.0/log_unstable.go:200-218`) retain pointers/slices, with no second value deep clone counted. The leader appendEntry clone above is real and distinct. `Put.Value -> val`, `val -> txnWrite.Put`, and `KeyValue.Value: value` are slice assignments (`source/server/etcdserver/txn/put.go:52-66`, `source/server/storage/mvcc/kvstore_txn.go:241-245`). MVCC index Put takes **key and revision, not value** (`source/server/storage/mvcc/kvstore_txn.go:259`, `source/server/storage/mvcc/index.go:54-66`): there is **no index value-set byte copy**. Backend write buffer stores k/v slice headers (`source/server/storage/backend/tx_buffer.go:204-210`); copying its kv structs is not copying payload bytes. Ordinary Put / successful Txn reply contains no new input value (no PrevKv), so its input-value reply stage is zero.

## 4. Existing stored value: MOD comparison and conditional failure reply

Unlike an index-only MOD fast path, stock etcd executes `rv.Range(..., RangeOptions{})` even for MOD (`source/server/etcdserver/txn/txn.go:268-291`); it then compares the revision (`source/server/etcdserver/txn/txn.go:312-316`). RangeOptions{} does **not** use FastKeysOnly. It fetches backend serialized KV and owns a decoded Value (`source/server/storage/mvcc/kvstore_txn.go:130`, `source/server/storage/mvcc/kvstore_txn.go:141-142`), using the same Google owning append shown above. No lease/PrevKv/Ignore flag causes another successful-Put pre-read (`source/server/etcdserver/txn/put.go:104-115`).

| Stored 1 KiB value stages on leader | CAS succeeds | CAS fails | Exact sites |
|---|---:|---:|---|
| Decode existing KV to evaluate MOD_EQUAL | 1 | 1 | Range/decode and compare sites immediately above |
| Decode existing KV for executed Failure.Range | 0 | 1 | selected branch `source/server/etcdserver/txn/txn.go:137-162`; range call `source/server/etcdserver/txn/range.go:62-71`; backend owning decode above |
| Encode Failure.Range.Value in gRPC TxnResponse | 0 | 1 | server response encoding `deps/google.golang.org_grpc@v1.83.2/server.go:1187-1189`; codec alternatives `deps/google.golang.org_grpc@v1.83.2/encoding/proto/proto.go:64-78`; Google bytes append above |
| **Known immediate stored-value subtotal** | **1** | **3** | a different payload identity from the new proposed value |

Backend Range returns value slices, not another owning value clone (`source/server/storage/backend/read_tx.go:79-93`, `source/server/storage/backend/read_tx.go:120-121`, `source/server/storage/backend/batch_tx.go:187-205`). Returned KV pointer construction and response assembly are not counted as copies. Failure returns a fresh decode of the old stored value, not the already-decoded comparison object or the unexecuted new Put.Value. Comparison failure is a successful Txn RPC with Succeeded=false, not a rejected proposal. The full success Put remains in Raft/WAL/apply decode, but no new backend KV marshal occurs.

With both values 1 KiB, **Put = 8 new stages; CAS success = 8 new + 1 stored; conditional CAS failure = 7 new + 3 stored**, before optional C and deferred/peer/excluded work. These sums cover different payload identities and are not nine/ten copies of one new input value. For T Txns and f actual failures, the explicitly counted immediate leader payload equivalents are `(8T-f)` new plus `(T+2f)` stored = `9T+f`, plus actual codec-coalescing population. Measured f=0: 300,000 etcd Txns give 2,400,000 new-value stages and 300,000 stored-comparison stages in this scope. The failure branch table is **conditional source analysis**, not an observed measured charge.

## 5. Deferred backend and peer stages — separate populations

**bbolt persisted page materialization is real but not a fixed request-time stage.** Stock backend uses batchTxBuffered (`source/server/storage/backend/backend.go:251`); UnsafeSeqPut calls both bbolt and its header-only buffer (`source/server/storage/backend/batch_tx.go:393-395`). The bbolt Put caller is `source/server/storage/backend/batch_tx.go:163`; bbolt `Bucket.Put` clones the **key** and retains the encoded **value** (`deps/go.etcd.io_bbolt@v1.5.0/bucket.go:476-492`), not a new full value copy there. At backend commit/spill, node serialization writes each resident serialized KV's full value into a dirty page (`deps/go.etcd.io_bbolt@v1.5.0/node.go:334`, `deps/go.etcd.io_bbolt@v1.5.0/node.go:199`, `deps/go.etcd.io_bbolt@v1.5.0/internal/common/inode.go:100-101`). Count one full value stage **per actual occurrence of that KV in a serialized leaf page**, not one channel or page per request. Successful writes create new revision KVs; a failed compare creates none. Thus two named new-value backend boundaries disappear on failure: the immediate KeyValue marshal and the deferred leaf-page serialization. Only the former is in the immediate subtotal above. A page can also serialize older residents again, so total page-payload stages cannot be inferred from requests or an invented backend batch size. bbolt remap/dereference can additionally copy resident values (`deps/go.etcd.io_bbolt@v1.5.0/node.go:478-481`); its population is unknown here. No physical backend total is claimed.

**Established peer streaming:** one sender encoding of a transmitted Entry.Data occurrence copies the full new value. MsgAppV2 alternatives: `source/server/etcdserver/api/rafthttp/msgappv2_codec.go:114`, `source/server/etcdserver/api/rafthttp/msgappv2_codec.go:122`, `source/server/etcdserver/api/rafthttp/msgappv2_codec.go:143`; receiver owning Entry.Data / Message decode: `source/server/etcdserver/api/rafthttp/msgappv2_codec.go:227`, `source/server/etcdserver/api/rafthttp/msgappv2_codec.go:243`. General-message stream equivalents are `source/server/etcdserver/api/rafthttp/msg_codec.go:38`, `source/server/etcdserver/api/rafthttp/msg_codec.go:69`. Their bytes operations are the same pinned Google proto2 encode/owning-decode above. These are alternatives, not additive for one transmission.

For one new follower entry received, newly WAL-persisted, and applied: **successful Put / CAS new input = 1 peer owning Entry.Data decode + 2 WAL protobuf encodes + 1 WAL PageWriter + 1 apply owning Put.Value decode + 1 backend KV marshal = 6 stages**; compare failure = **5** (no backend KV marshal). Sender encode adds one per transmitted occurrence, separately from the leader's eight-stage subtotal. Followers still read/decode existing value for the comparison (one stored-value stage), but skip executing the failure Range when no origin waiter is registered (`source/server/etcdserver/apply/apply.go:40-46`, `source/server/etcdserver/txn/txn.go:151-162`) and do not encode this client's response. Raft follower appending received entry pointers is not leader appendEntry's clone. Deferred bbolt stages remain separate on each follower as on leader. Retransmission, fanout, catch-up, receive accumulation, quorum timing, and actual occurrence counts are unknown here; **no factor of two followers, no one-fsync/request, and no universal cluster total** is assigned.

## Bottom line

- **Core/request/reply:** known fixed **3 sends + 3 selected receives**, **2 closes**, **2 fresh reply channels** per completed Put or either CAS outcome. Ready, scheduler and peers are additional symbolic/batched work.
- **Immediate leader payload:** Put **8 new-value stages**; CAS success **8 new + 1 stored-comparison**; conditional failure **7 new + 3 stored**. Optional grpc codec coalescing, deferred bbolt leaf serialization, peers, and exclusions are explicit, not silently zero.
- Actual measured comparison failures are **zero**. This is a source census only; no performance claims. This subtotal includes stock WAL PageWriter staging but separates deferred bbolt page serialization; transport accumulation boundaries also differ from Tigerstore. In particular, **4 versus 8 is not a physical-copy ratio**.
