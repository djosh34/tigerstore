# etcd v3.7.2 robustness audit for external tigerstore endpoints

Source-only audit, 2026-10-13. No builds, test execution, subagents, or GitHub comments. This audit does not verify tigerstore's API implementation or the parent's Jepsen control run.

The annotated `v3.7.2` tag resolves to commit [`68c065e562994b89e333e77b039ad066f933c586`](https://github.com/etcd-io/etcd/tree/68c065e562994b89e333e77b039ad066f933c586/tests/robustness). All source links below pin that commit. The retained [`evidence/robustness/`](evidence/robustness/) files `tag.json`, `tag-object.json`, `tree.json`, and `source-manifest.json` record the provenance. All 64 downloaded source files match their Git blob hashes.

## Decision

Reuse the recording client and Porcupine validator. Do not run `TestRobustnessExploratory` or `TestRobustnessRegression` against external endpoints. Both create local etcd processes; neither accepts an external cluster instead. Their shared runner also reads etcd WALs. See [`main_test.go:53-126`](https://github.com/etcd-io/etcd/blob/68c065e562994b89e333e77b039ad066f933c586/tests/robustness/main_test.go#L53-L126).

These clients assume tigerstore exposes etcd v3 gRPC services. For another protocol, replace the wire client and translate requests/responses into `model.EtcdRequest`, `MaybeEtcdResponse`, and watch records. Preserve revisions, key versions, transaction results, uncertain errors, and operation intervals. Endpoint strings alone cannot adapt different semantics.

The largest correctness trap is `ValidateAndReturnVisualize(..., nil, ...)`. It checks KV linearizability, then **skips all watch and historical-read validation**. `result.Error()` still returns nil when those checks remain unrun. Assert explicit result statuses and report skipped coverage.

## Traffic choices and adapters

The exported presets `traffic.EtcdPutDeleteLease`, `EtcdPut`, and `EtcdDelete` implement `Traffic`. Their concrete `etcdTraffic` type is private, but its methods are callable through that interface:

- `RunKeyValueLoop(ctx, c, RunTrafficLoopParam)` dispatches through private `etcdTrafficClient.Request`. It records point/prefix reads, fixed-revision reads, puts, deletes, four-operation transactions, CAS, and lease operations according to the preset.
- `RunWatchLoop` watches the key prefix with progress and previous values. Default randomized revision offsets include historical and future revisions.
- `RunCompactLoop` calls `Status` to choose revisions, then `Compact`.
- `ExpectUniqueRevision()` returns false because multi-key writes share a revision.

`EtcdPut` is not a put-only workload. It includes streamed range reads, historical reads, and mixed transactions that can delete. `EtcdDelete` is the narrowest preset, 50% put and 50% delete. For a controllable API subset, write a small traffic implementation or expose configurable request weights in a fork. The presets' weights cannot be changed through exported configuration. Defaults are a 200 ms request timeout, 500 ms short watch timeout, and 7200-second lease TTL. These are test defaults, not a suitable remote-service latency contract.

Sources: [`presets and loops`](https://github.com/etcd-io/etcd/blob/68c065e562994b89e333e77b039ad066f933c586/tests/robustness/traffic/etcd.go#L33-L197), [`request dispatch`](https://github.com/etcd-io/etcd/blob/68c065e562994b89e333e77b039ad066f933c586/tests/robustness/traffic/etcd.go#L217-L412), [`defaults`](https://github.com/etcd-io/etcd/blob/68c065e562994b89e333e77b039ad066f933c586/tests/robustness/traffic/traffic.go#L49-L91).

`traffic.Kubernetes` and `KubernetesCreateDelete` also implement `Traffic`. They use `client/v3/kubernetes`, not a Kubernetes cluster. Private `kubernetesTraffic` implements `Read`, `Write`, `List`, `Watch`, and `RunCompactLoop`. It uses optimistic transactions, paginated lists at a fixed revision, `/registry/pods/` watches with `WithRequireLeader`, and a `compact_rev_key` CAS. Its uniqueness flag is true. Leave it out of the first CI job; add it after basic revision, CAS, pagination, and watch semantics work. [`kubernetes.go:33-338`](https://github.com/etcd-io/etcd/blob/68c065e562994b89e333e77b039ad066f933c586/tests/robustness/traffic/kubernetes.go#L33-L338).

Do not adapt `traffic.SimulateTraffic` by merely replacing its endpoint lookup. It takes `*e2e.EtcdProcessCluster`, waits for a failpoint report, computes before/during/after statistics, requires minimum pre-failure QPS, and writes a final `tombstone`. Use its lower-level exported starters with your own stop/drain sequence. Initialize `RunTrafficLoopParam` with a rate limiter, shared IDs, `identity.NewLeaseIDStorage()`, `traffic.NewConcurrencyLimiter(n)`, `traffic.NewKeyStore(10, "key")`, `traffic.NewKubernetesStorage()`, and a `Finish` channel. The private storage types can be populated through these exported constructors. [`traffic.go:93-183`](https://github.com/etcd-io/etcd/blob/68c065e562994b89e333e77b039ad066f933c586/tests/robustness/traffic/traffic.go#L93-L183).

## Model and watch traps

1. **Fresh storage is mandatory.** `freshEtcdState` starts empty at revision 1. Validation requires a recorded read with response revision 1. Deleting a prefix does not reset the global revision. A unique prefix on a shared database is insufficient. Provision a fresh, exclusively owned endpoint group, or explicitly change model initialization. Do not bypass the assumption check. [`initial state`](https://github.com/etcd-io/etcd/blob/68c065e562994b89e333e77b039ad066f933c586/tests/robustness/model/deterministic.go#L127-L138), [`assumptions`](https://github.com/etcd-io/etcd/blob/68c065e562994b89e333e77b039ad066f933c586/tests/robustness/validate/validate.go#L114-L158).
2. **Timeouts are uncertain writes.** Private `prepareAndCategorizeOperations` sets failed operations' return time to `math.MaxInt64`, drops failed reads and defragmentation from linearization, and identifies fixed-revision ranges for separate checking. `NonDeterministicModel` considers both applied and unapplied states for failed writes. `AppendableHistory.appendFailed` allocates a new stream ID after an uncertain write. Preserve this behavior when adapting a non-etcd wire client. [`history.go:304-339`](https://github.com/etcd-io/etcd/blob/68c065e562994b89e333e77b039ad066f933c586/tests/robustness/model/history.go#L304-L339), [`non_deterministic.go`](https://github.com/etcd-io/etcd/blob/68c065e562994b89e333e77b039ad066f933c586/tests/robustness/model/non_deterministic.go#L161-L236).
3. **This is an etcd semantics model.** It checks global revisions, per-key versions/mod revisions, range results/counts, transaction branches/results, and leases. Older fixed-revision reads receive only partial checking in the linearizability model; replay validates their contents separately. Lease expiry is not modeled. The workload's long TTL avoids autonomous expiry. Unsupported transaction conditions/nested transactions can panic; transaction option conversion does not preserve every etcd option. `RecordingClient.Get` does not preserve `WithSerializable`; `Put`, `Delete`, and `Compact` ignore their variadic options. Use only recorded semantics. [`deterministic.go:159-325`](https://github.com/etcd-io/etcd/blob/68c065e562994b89e333e77b039ad066f933c586/tests/robustness/model/deterministic.go#L159-L325), [`operation conversion`](https://github.com/etcd-io/etcd/blob/68c065e562994b89e333e77b039ad066f933c586/tests/robustness/model/history.go#L206-L244).
4. **Watch validators are private.** `validateWatch` calls `validateFilter`, `validateOrdered`, `validateUnique`, `validateAtomic`, `validateBookmarkable`, `validateResumable`, `validateIsCreate`, `validateReliable`, and `validatePrevKV`. The first five need only recorded watches. The remainder need replay states/events. Expose a wrapper in a pinned fork for watch-only checking, or use the public combined validator with valid replay input. For generic etcd traffic, set `ExpectRevisionUnique:false`; true would reject valid multi-key revisions. [`watch.go:42-95`](https://github.com/etcd-io/etcd/blob/68c065e562994b89e333e77b039ad066f933c586/tests/robustness/validate/watch.go#L42-L95).
5. **Watch safety checks do not prove delivery deadlines.** Reliability compares expected events only through the last observed event/progress revision. Resumability permits no first event. Previous-value validation permits a nil previous value because of compaction. Add a bounded sentinel drain, event-count assertions, and progress-notification assertions rather than accepting an empty/stalled watch as success. [`reliability/resumability`](https://github.com/etcd-io/etcd/blob/68c065e562994b89e333e77b039ad066f933c586/tests/robustness/validate/watch.go#L196-L253), [`previous values`](https://github.com/etcd-io/etcd/blob/68c065e562994b89e333e77b039ad066f933c586/tests/robustness/validate/watch.go#L256-L295).
6. **Bound startup and watch drain yourself.** `CheckEmptyDatabaseAtStart` retries errors without checking parent cancellation. Private `watchUntilRevision` has no `ctx.Done()` select branch; cancellation can close the watch and repeatedly reopen it. It advances its drain position on events, not progress headers, and can skip compacted history. Replace it with a bounded loop that returns on cancellation, fails on compaction in a no-compaction test, and confirms the sentinel on every endpoint.
7. **A nil error can conceal missing coverage.** Empty watch histories can pass; nil persisted requests leave watch/serializable status unknown. `Result.Error` accepts unknown status. Porcupine timeout and its internal deadline are failures, not passes. The validator uses a global deadline flag, so avoid concurrent validations. Its visualizer skips failed linearizations. [`deadline handling`](https://github.com/etcd-io/etcd/blob/68c065e562994b89e333e77b039ad066f933c586/tests/robustness/validate/operations.go#L34-L84), [`result handling`](https://github.com/etcd-io/etcd/blob/68c065e562994b89e333e77b039ad066f933c586/tests/robustness/validate/result.go#L48-L111).

## Smallest useful CI integration

Proposed implementation only. Nothing below was run.

Add one separate package, for example `tests/tigerstore_robustness`, to a full checkout of the pinned etcd commit. Import `client`, `identity`, `model`, `report`, and `validate`. Do not inherit robustness's `TestMain` or invoke its Make targets. This needs no upstream validator changes for the initial success-only test.

1. Require `TIGERSTORE_ENDPOINTS` and explicit permission to use fresh disposable storage. Fail setup if missing in CI. Record an initial empty read at revision 1 before any write. Use one process for all client timing.
2. Run one sequential writer for about 100 mutations over ten keys, plus two recording readers with about 100 total reads. Include puts, distinct-key multi-put transactions, and deletes of keys known to exist. Readers use current ranges and a few known fixed revisions. Exclude leases, streamed ranges, compaction, defrag, and faults initially. Use short unique values to avoid the model's lossy hash representation.
3. Start a full-prefix recording watch at revision 2 on each endpoint, with progress and previous values. Use a bounded drain loop, not unchanged `CollectClusterWatchEvents`. Exercise at least one cancel/resume at the last complete revision plus one. Record a final sentinel put. Require every endpoint watch to reach it and at least one requested progress notification to arrive.
4. Require every KV request to succeed. Any RPC error makes this success-only job fail as an execution failure; do not pretend its replay is complete. Build an ordered request list from the recorded writer inputs, including the sentinel. Check that each mutation advanced exactly one revision, starting at 2. One sequential writer and no other writers make this a usable replay input. It is an acknowledged client history, **not durable-log evidence**.
5. Call `ValidateAndReturnVisualize(lg, validate.Config{ExpectRevisionUnique:false}, reports, orderedWrites, 10*time.Second)`. Require `Assumptions`, `Linearization`, `Watch`, and `Serializable` to equal `validate.Success`, plus the explicit drain/coverage assertions. Save typed operations and watches, replay requests, endpoint/version metadata, and result statuses on every failure.
6. Give the whole job a hard timeout, for example two minutes. Build/run on a CI worker, not this host. Cache the runner artifact. A later execution command, not executed here, is `GOFLAGS=-p=2 GOMEMLIMIT=2GiB TIGERSTORE_ENDPOINTS=... go test ./tigerstore_robustness -run '^TestExternalTigerstore$' -count=1 -timeout=2m` from the checkout's `tests` module.

This first job checks bounded KV histories and watch delivery against acknowledged writes. It does not establish crash durability. For a faulted extension, run black-box KV validation with nil persisted requests and label watch/historical-read replay checks skipped. Add replay-dependent fault checks only after a trustworthy tigerstore log adapter exists. Compare a healthy etcd endpoint control with the same runner before treating tigerstore failures as implementation bugs.
