# Round 2 fault campaign

This branch tests main `5d964228952d6983ba273bc2e6813770aad796c6` without product changes. It reuses round 1's cluster lifecycle, stock etcd client, watch recorder, persisted-log converters and all four repository checkers. The independent workflow is `.github/workflows/correct-round2-faults.yml`. All faults run in private network/mount namespaces on free GitHub-hosted runners. At most four jobs run at once.

The full matrix has five schedules, two products, two runner architectures and two repetitions, 40 cases. `campaign.json` selects the next batch; `full-campaign.json` is the intended full matrix. Seed 149 drives clients and role choices. Runtime and election timing are not deterministic.

- Partition the old leader's outgoing peer packets, observe a replacement leader on the remaining pair, and SIGKILL that replacement while the partition remains installed. Hold two seconds, restart and heal. Known watchdog self-fences retain their evidence and restart after healing. Other exits fail the case.
- Cut one survivor's outgoing peer packets to hold the election open. Kill the old leader, observe both survivors reporting leader ID zero through Status-only RPCs, then SIGSTOP the cut survivor for three seconds during that leaderless election interval. The fault is not a named Raft instruction boundary. Require waitpid, all task states stopped and unchanged CPU ticks. Resume and restart the old leader.
- Fill the elected leader's private 256-MiB ext4 filesystem to ENOSPC. A marker barrier parks all 256 logical clients, spread 86/85/85 across the three member-pinned connections. After verified filesystem ENOSPC, release one unpaced Put request per client, 256 recorded burst writes. After that Put, each client issues only reads until the controller publishes a healed marker. The earlier eight-Put pilot retains its 2,048-write burst and failed whole-history checker verdicts. Require the server itself to exit with an ENOSPC log, free space and restart. Keep all timed-out writes ambiguous.
- Drop only one node's outgoing peer TCP packets for five seconds. Reverse packets and client/watch/control ports do not match the rule. This is asymmetric packet loss, not a guarantee that TCP reverse streams continue indefinitely; missing ACKs eventually affect both byte streams.
- Flap that outgoing packet cut six times, alternating 0.4-second and 1.2-second cut holds with 0.3-second healed intervals. Each installation requires actual dropped peer TCP packets.

Normal schedules use three sequential logical clients, six hot keys and two operations per client per second for 40 seconds. The disk schedule uses 256 clients, two keys and a three-second per-client interval for 30 seconds, plus the bounded burst. Every client issues one immediate initial operation for pre-fault traffic. The nominal disk offered rate is about 85 operations/second outside the burst, not a saturation throughput claim. Every call is recorded, including ambiguous failures, terminal barriers and reads. Watch clients are separate from unary client IDs; all three member-pinned logical watches request `prev_kv`. After healing plus a ten-second election/client-reconnect allowance, every unary client must make progress and all calls that start then must succeed within their two-second request deadlines. The coverage floor requires every expected unary client to have a successful operation, all mutation/read shapes, multi-key deletion, watch puts/deletes/previous values and progress through the terminal revision.

Original stopped disks and each cold surviving pair produce four repository-format history variants. All four checkers run on each. Full-history Porcupine has a 30-second deadline and no partitioning or writer omission. A timeout, missing checker verdict, missing actual fault hit or failed setup is FAILED. These are not automatically product defects. If log conversion fails, check the saved raw history under that variant's name anyway. If no manifest exists, check any recorded raw history. If no history was recorded, report a failed attempt with zero histories rather than invent a checker result.

Artifacts retain disks, operation/watch histories, faults and command logs. The permanent archive excludes bulky server disks and stores gzip files with a base-compatible `manifest.json` containing original path, SHA-256 and byte size. `attempt.json` preserves matrix coordinates and step outcomes even for build/setup failures. Count attempts that reached the controller separately. Do not rerun away earlier failures.
