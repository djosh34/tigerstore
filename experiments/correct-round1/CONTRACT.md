# Correctness round 1 client contract

Throwaway helper. Build from this directory with `GOFLAGS=-p=2 GOMEMLIMIT=2GiB go build -o client-tool ./client`. The nested module replaces the root module with `../..`. No product files change.

Network modes require `--endpoints` as a CSV of pinned HTTPS endpoints, `--cacert`, `--cert`, and `--key`. No automatic endpoint discovery or load balancing across members. Runner orchestration owns process startup, faults, healing and shutdown. Run network modes only on GitHub runners.

- `status` prints JSON `{nodes:[{endpoint,member_id,leader_id,...}]}`. IDs are decimal strings. Each endpoint must answer Status and a linearizable Range to be ready. Nonzero on any unready endpoint. Two endpoints are allowed for cold pair recovery.
- `workload`, alias `run`, takes `--duration 65s --seed 49 --clients 3 --rate 5 --out DIR --stop-file PATH`. Rate is per client and defaults to 5 operations per second. One sequential client per pinned endpoint. Six hot keys by default. The workload records Put, MOD/VERSION CAS transactions, range deletes and linearizable reads, plus a prefix watch pinned to each member. The default request timeout is 2s, configurable with `--request-timeout`. A stop marker or duration ends new operations. After in-flight requests return, an 8-second quiet suffix lets timed-out server requests drain. Three recorded write-shaped failed CAS barriers append without changing the KV revision. These move the persisted commit prefix beyond the last KV mutation, including on stock etcd. Full linearizable reads from all three endpoints must then agree and fix the watch target. Watches must receive progress through that target before saving `history.json` and `receipt.json`. Errors and ambiguous outcomes stay in the history. No offline oracle exists yet at this stage, so this mode does not claim checker success.
- `verify`, alias `inspect`, takes `--receipt FILE --out FILE` plus TLS flags. It compares each supplied endpoint's full linearizable range and revision with the saved terminal receipt. Use after recovery with no intervening writers. Nonzero on any mismatch. Pair-only endpoints are allowed.
- `log` takes `--backend tigerstore|etcd --data-dirs CSV --history FILE --out FILE --stopped-file PATH`. All nodes must be stopped and the orchestrator must create the marker after reaping them. It reads preserved WAL files offline, takes only the recovered hard-state commit prefix, cross-checks committed prefixes, decodes requests, and writes a History with Log populated. It also saves `FILE.oracle.json` with each member's persisted commit and last index plus the first uncommitted entry's hash and decoded requests, if present. An uncommitted tail is diagnostic evidence, never part of Log. Independently replaying the committed mutations must end exactly at Target. It must not mutate original WAL files. Fresh clusters only, no snapshots, leases, compaction or outside writers in this first workload.
- `check` takes `--history FILE --checker-timeout 30s --out FILE`. It runs Linearizable, Watches, Durable and Revisions, prints a separate result for each, saves JSON and `FILE.coverage.json`, and fails on checker error, timeout, empty operations/log/watches or missing positive target. It requires successful Put, both CAS branches, Delete, a multi-key Delete, Range, success on each of the three clients, and watch puts/deletes/previous values and progress through Target. Coverage errors join each checker result instead of silently skipping a checker. Oracle construction failure is not a pass.

`--value-size` defaults to 1024 bytes of stamped ASCII data. The stock client has `MaxUnaryRetries:1` and gRPC retries disabled. Watch streams keep stock reconnect behavior, with an outer no-leader resume from the last delivered event revision or progress revision. `watch-responses.json` retains every client-visible response, including transient transport diagnostics. A terminal no-leader/transport error does not cancel the logical resumed watch in History. The tool saves raw history and receipt even when terminal reads or watch finalization fail.

The parent calls `log` and `check` after shutdown. A runner should retain the original receipt, raw history, WALs, enriched history and checker output even when a command fails. A passed receipt comparison is not a substitute for the four checkers or proof of power-loss durability.
