## What each checker does

History length alone is insufficient for a complexity bound. Let L be log entries, K the distinct potentially writable keys, E the log's generated key events, D all observed key/event records, W watch streams, C compactions, lambda active leases, and B bytes examined. These can all grow independently of n and a. Every public checker also runs `History.Validate`: per-client sorting costs O(n log n) in the worst case, plus validation of requests, log entries and watch events. This work is repeated by every checker.

- **Linearizable, `check/linearizable.go`, `model.go`.** Porcupine explores legal call orders with cached states. An unresolved ambiguous mutation forks the model into took-effect / did-not-take-effect states. Effects constrain some forks and return windows. Model steps clone K keys and lambda leases; fingerprinting scans them. Orders can be exponential/factorial in concurrency, and state sets can grow as 2^a. There is no polynomial bound in n,a. This model installs no Porcupine Partition function: it does not use P-compositionality. Multi-key transactions, range reads and the global revision also prevent blindly partitioning by key. `ShortEnough` gates ordinary Porcupine use at 4,000 operations.

- **Witnessed FromLog, `check/witness.go`.** Replay the log. Fingerprint requests. Claim acknowledged mutations, then ambiguous ones. Place non-changing observations in the first matching state of their header revision, subject to real-time bounds. Use sorted endpoints, binary searches and a Fenwick maximum tree; finally verify real-time order. There is no order backtracking. However, `stateAt` rebuilds K keys from historical versions when the revision changes, and clones K keys plus lease lists for every answer probe. Typical work includes O(n(K+lambda)), historical lookup cost and O(n log n). `find` can probe L states per observation, yielding O(n L (K+lambda+model-query-cost)) worst-case probe work. Matching repeated identical request fingerprints can additionally cost O(nL). The unique-put-value workload avoids that matching worst case for puts, not for every API call. Retained space includes O(n+L+E+K) metadata and potentially O(L*lambda) copied lease summaries; the O(nK) key copies are mostly allocation churn.

- **Witnessed FromRevisions, `check/witness_revisions.go`.** Index acknowledged writers by revision. Resolve ambiguous puts from unique values observed by reads/watches. Bound gaps using real time, key lifetimes, unchanged spans, counts and lease uses. Depth-first search fills remaining gaps and can undo the entire suffix. Even a successful path scans/sorts up to a candidates at every gap: O(g a log a), before model work. Optional-event scans can cost O(L a); scheduling optional compactions scans observations. Gap snapshots clone K keys and the used-call map, producing O(g(K+a)) snapshot space on one path. General search can explore permutations of a candidates across g gaps. Failed observations can force those alternatives. `MaxSteps` bounds selected outer steps, not the cost inside a step.

- **Durable, `check/durability.go`, `replay.go`.** One independent model replay builds outcomes, events and per-key versions. Request fingerprints match acknowledged and ambiguous calls to log entries. Reads query historical versions; no-op compares and deletes are checked there. Expected matching work is linear with distinct requests; repeated identical requests can cost O(nL). A historical range over k potentially present keys costs O(k log v), where v is versions per key. Lease revoke scans K keys. Space is O(L+E+K), plus fingerprints and response bytes. It checks the recovered log supplied by the harness, not whether actual disk recovery produced that log.

- **Watches, `check/watch.go`.** Repeat the replay. Check each delivered event, previous value, progress bound, cancellation and stream order. Build the expected subsequence by scanning all E generated events separately for each watch. Cost includes O(W E + D), plus replay and compact-cancellation membership checks O(C) each. Indexed watch routing could avoid scanning unrelated events. Space includes replay and per-watch expected/received lists and duplicate maps.

- **Revisions, `check/revision.go`.** Index acknowledged revision writers. Sort return times and check real-time revision monotonicity. Collect key observations, compare metadata and writer identity, sort versions per key, verify delete coverage and compaction errors. Sorting is O(n log n + D log D). Several checks are quadratic: observed versions versus deletes of the same key, relevant calls versus C compactions, and W watches versus acknowledged writes. Thus worst-case O((n+D)^2), not merely O(n log n). Ambiguous calls enter compaction possibilities but do not trigger backtracking.

- **Model/replay helpers.** Sorted key arrays give point lookup O(log K), but ranges and revokes may scan K. Historical point lookup is O(log v). The model's range limit does not stop its count scan. These costs and payload bytes must appear in any honest per-operation bound.

- **Simulator-owned checks, `internal/sim/check.go`.** These are separate from the independent oracle. Decode the committed log; replay the actual state machine without compactions; compare final state and successful responses at their revisions. Cost is replay, touched/returned keys and bytes, not search in a. `checkRealTime` sorts call/return times: O(n log n). `checkLog` hashes unique put values: expected O(n+L+B). `leasesExpire` scans history twice and lease maps: expected O(n+leases), no ambiguity search. `checkWatchersFreed` counts open streams per live node: O(nodes*W). `checkWatches` in `watch.go` compares model history by stream segment and can rescan old events. `checkColdRestarts` in `faults.go` actually erases each disk in turn at every checkpoint and cold-starts the remaining quorum. Its cost depends on checkpoint count, disk bytes, recovery and elections, not just n,a. `checkRecoverable` opens each durable WAL and compares its recovered floor. Convergence/state hashes, membership rules, liveness and coverage/fault-effect assertions are additional checks. None is replaced by a client-history linearizability pass.

## The actual floor

General linearizability checking is NP-complete. That does not make exponential checking inevitable for these histories. The stronger observation is not just unique values: **we have a total order of committed state-machine requests and revisions naming the resulting KV states**.

A direct construction is:

- Replay mutations in their supplied order. Use the replayed semantics, not reported revisions, to validate the revision sequence and transaction atomicity.
- Match unique written values to calls and revisions. Resolve ambiguous value-producing effects with a hash index instead of branching.
- Validate each read against its requested revision, or its header revision for a current read. Validate previous values, compares, version/create/mod metadata and branch results while replaying.
- Place reads between the mutation that creates their header revision and the next mutation. Check real-time windows with sorted endpoint sweeps, or by greedily propagating the earliest feasible linearization time through the supplied order. Ambiguous calls have no finite return bound unless independent Effect evidence supplies one.
- Merge watch sequences against the corresponding generated events. Track leases, compactions and live state in maps/indexes. Reuse one replay instead of making every checker build it again, if oracle independence requirements permit that sharing.

The information lower bound is Omega(n+L+D+B): every relevant record and compared byte must be inspected. With unsorted comparison keys/endpoints there is O(n log n) sorting. Already ordered logs plus dense revision buckets and chronological endpoints can remove that sort; fixed-width radix sorting also avoids a comparison-sort lower bound. For bounded-size point operations and fixed watch fanout, expected amortized linear work is attainable. Arbitrary range queries/deletes, huge payloads, historical indexes and unbounded overlapping watches are not constant-cost operations. A practical ordered-index version is O((n+L) log K + affected/output records + bytes), plus endpoint sorting and historical lookup costs. There is no required exponential term in a when effects and their total order are known.

**Important qualifications.** A unique value in the *raw request* log is not itself proof that the put ran: a CAS can take its read-only failure branch, and a lease error can reject a put. Use replayed applied effects. Unique values do not identify deletes, compactions, lease grants/revokes or autonomous expiries. Those need log request identity, lease/revision metadata, or matching against the known order and time windows. A value absent from a partial read/watch history may have been overwritten unseen; absence proves non-effect only with a complete log/effect record. The log-free witness intentionally withholds that extra information. Replacing it with a log witness loses an independent oracle, even if the replacement is sound as an existence-of-linearization test.

Primary references:

- Gibbons–Korach, *Testing Shared Memories*, DOI `10.1137/S0097539794279614`. General hardness is also discussed explicitly in Lowe's original paper. I could not inspect the publisher's full Gibbons–Korach text; I do not claim a theorem that unique values make arbitrary multi-key etcd programs polynomial.
- Lowe, *Testing for Linearizability*, original paper: https://www.cs.ox.ac.uk/people/gavin.lowe/LinearizabiltyTesting/paper.pdf . It states general NP-completeness and an O(n log n) fixed-processor register special case. Its search algorithms do not make arbitrary models polynomial.
- Horn–Kroening, *Faster linearizability checking via P-compositionality*: https://arxiv.org/html/1504.00204v1 . Porcupine's own README identifies this and Lowe as its algorithm sources: https://github.com/anishathalye/porcupine . Partitioning reduces independent search spaces; it does not replace a known global revision order.
- Kingsbury–Alvaro, *Elle*: https://arxiv.org/html/2003.10554 . Sections on version orders and inferred dependencies explain why recovering version order matters. Once the dependency graph exists, cycle detection is linear in vertices plus edges. Elle's isolation-anomaly inference is not a complete executable etcd/lease/watch validator.
- etcd v3.7.2's primary implementation: https://github.com/etcd-io/etcd/tree/v3.7.2/tests/robustness/validate . `patch_history.go` uses persisted requests and unique put/delete operations to drop known-nonpersisted failed transactions, constrain persisted revisions and shorten return bounds. `operations.go` still invokes Porcupine's nondeterministic model. `validate.go` separately replays persisted requests for watch and serializable-read validation. etcd does not simply leave every failed request as an unresolved branch.

## Throwaway prototype

`check/exp448_floor.go`, entry point `Floor448`, is a **KV-projection checker**, not a complete replacement. `cmd/checkfloor` benchmarks it. It sorts successful non-changing operations by header revision, replays the log once, checks those observations against the live state, and keeps per-key versions for historical reads. It indexes value-bearing requests by their first unique put value without copying the value. It checks full request equality before claiming a log event. Non-value requests use a content fingerprint. It never clones the whole key state per observation. It then sweeps call/return times, including applied ambiguous writes, against replayed revisions. It passes all four saved histories and the controlled histories. `TestFloor448Projection` checks valid data, wrong values/versions, stale reads, applied ambiguity, impossible ambiguous-call timing and duplicate commits.

Measured native prototype cost and memory, `e302458e`, run `40284568996`:

| History | Median ns/op | Allocated bytes/op | Reachable auxiliary heap bytes/op |
|---|---:|---:|---:|
| Default | 1,309 | 854 | 356 |
| Short kube | 1,802 | 960 | 423 |
| 60 minutes | 1,971 | 733 | 288 |
| 120 minutes | 2,153 | 715 | 277 |

Allocated bytes use `runtime.MemStats.TotalAlloc` deltas, excluding history decoding. Reachable workspace is a separate untimed run: GC before the check and again at its end, while `runtime.KeepAlive` retains all workspace arrays/maps; subtract the input-history heap baseline. It is neither total process RSS nor a proof of peak heap. The largest measured retained workspace is 33.293 MiB: 277 bytes/op times 125,998 operations, using unrounded JSON values. Its total allocations are 85.957 MiB. Memory is O(n+L+E+K), sharing input strings rather than copying values. A streaming checker could retain less; arbitrary historical queries prevent discarding all old versions unconditionally.

For contrast, the current completed 60-minute witnesses allocate about 128,950 and 386,383 bytes/op respectively, from the same benchmark's TotalAlloc deltas. Their full-state and search-snapshot copies are allocation churn, not inherently required checker state.

The prototype's short kube gosim cost is 3,754 ns/op, from `40284568996`: 0.007185561 seconds / 1,914. Local arm64 native short-history measurements are also saved in this worktree; the 60-minute prototype is 1,323 ns/op locally, median-of-three from `GOMAXPROCS=2 GOFLAGS=-p=1 research/448/checkfloor -repeat 3 -checkers floor .../441-9002/history.json.gz`. Cross-host ratios are not used as same-hardware speedups.

Coverage:

- Covers history format/client serialization validation; replayed mutation responses, compares, branches, previous values and atomic revision increments; successful current/historical/serializable Range data; successful non-changing transactions and deletes; exact metadata/value equality in those responses; acknowledged mutation membership, duplicate/unclaimed value-producing log entries; and revision-based real-time bounds including matched ambiguous effects.
- Does **not** place non-revision-changing lease/compaction operations in a complete real-time witness. It deliberately ignores compaction while validating successful historical-read data. It does not validate semantic-error placement or all error codes. It does not independently prove complete linearizability of the full API.
- Does **not** check watches, lease TTL/clock envelopes, watcher leaks, membership, replica convergence, actual WAL recovery, erase-one-disk survival, or liveness/fault coverage. It uses the existing independent deterministic model, rather than supplying another independent semantic implementation.
- Its repeated-identical non-value-request matching can still be quadratic. Its ordered key array and historical queries retain the model's range/index costs. The prototype demonstrates removal of the dominant copies/search for this workload; it is not a proof that the complete checker floor is exactly its measured ns/op.
